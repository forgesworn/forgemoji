# ForgeMoji

**Familiar emoji. Our own artwork.** Created by **TheCryptoDonkey** for **ForgeSworn**.

An original set of everyday emoji illustrations: recognisable faces, human hands, hearts, animals, food and useful objects. Each image maps to ordinary Unicode, so a thumbs-up message is still `👍`, or `👍🏽` with a chosen human skin tone. No private shortcode protocol is needed.

The first collection contains **124 Unicode emoji or currency symbols (including our orange Donkey, a cute black LittleLeap jumping spider, Bitcoin and the 600 sacred stone), nine ForgeSworn brand shortcodes, and 30 human skin-tone variants**: **163 scalable SVGs and 163 transparent 192×192 PNGs**. All six hand gestures have a yellow default plus five human tones. This is a deliberate everyday selection; it does not cover the entire Unicode emoji standard. Flags and character sticker packs are outside this collection. The ForgeSworn collection contains the existing ForgeSworn, Kindred, KithMoot, MySignet, Vitark, Den, Train, Still and Record marks. Eight retain their existing SVG masters; the ForgeSworn anvil has a vector reconstruction from its PNG master.

## Bundle in an app

The package is `@forgesworn/forgemoji`. The source repository can be vendored or installed from a pinned Git commit. Copy the selected `svg/` or `png/` files into your own application's static assets or native resources. A renderer should use `manifest.json` to resolve known Unicode sequences, preserving the underlying message text. Unknown emoji should fall back to the platform font. The Bitcoin entry is the standard currency symbol `₿` (U+20BF), explicitly marked `kind: "symbol"`; it is not part of Unicode Emoji 16. Brand entries use `kind: "custom"` and category `forgesworn`, with exact `:fs_*:` shortcodes such as `:fs_kithmoot:`. Unknown shortcodes must remain plain text.

```js
import { definitions, vectorArtwork, withSkinTone } from '@forgesworn/forgemoji';

const unicode = withSkinTone('👍', 3); // 👍🏽
const image = vectorArtwork.find(entry => entry.emoji === unicode);
// image.file is svg/thumbs-up-tone3.svg. Resolve against your local assets.
```

`artwork` remains the original PNG metadata export. `vectorArtwork` is the parallel SVG export, with the same Unicode, slugs and skin tones. Both include file paths, byte counts and SHA-256 hashes.

Tone `0` is the yellow/default artwork; `1` to `5` correspond to Unicode modifiers U+1F3FB through U+1F3FF. `withSkinTone` removes an existing modifier before applying the chosen tone and leaves unsupported emoji unchanged. Some base sequences include variation selector U+FE0F; normalise selectors when matching a platform's text input, and use the manifest's canonical sequence when sending.

The module only exposes metadata and Unicode helpers. It does not fetch images, contact an API, inject a CDN, perform analytics or access the network. Bundling images prevents preview requests to a graphics provider; network behaviour elsewhere in your app remains your responsibility.

## Sources and reproducible build

`sources/` contains the original sprite sheets, `prompts/` the exact generation/edit prompts, and `scripts/definitions.mjs` the semantic row/column mapping. Original artwork was generated with explicitly selected **GPT-Image-2.5 Sunburst** (`gpt-image-2.5-sunburst`, high quality), using only our own approved artwork as the style reference. The sacred stone is a new illustration using the primary [600 community stone](https://600.wtf/img/sacred-stone.webp) as a semantic reference. The reference photograph is not redistributed or included under this licence. Its marking reads four rows: `600 / 000 / 000 / 000`, totalling `600000000000`. It maps to ordinary rock Unicode `🪨`; other clients may display their standard rock. The original illustrations are raster sources. Their SVG counterparts are fitted reconstructions containing paths, gradients, masks and small filters, with no embedded raster images, scripts or external resources. The approved happy-face rebuild supplies the shared golden shading of the remaining measured faces. Existing owned brand masters are retained.

The owner-feedback pass restores the PNG proportions, anatomy, colours and shading for the reviewed animals, all 36 hand variants, food and useful objects. `scripts/detailed_vectors.py` fits cubic contours at the original resolution and reconstructs continuous colour ramps from bounded colour controls. These colour surfaces retain finite source detail; enlargement does not create new photographic detail. The spider uses the detailed 1024px source, retaining reflective eyes, fur and joint shapes in native vector colour regions. The stone SVG now follows the primary community photograph's silhouette, texture and irregular marking rather than the earlier illustrated PNG; the consulted photograph is not included in the package. Its source URL and checked SHA-256 are recorded, and reauthoring verifies the reference has not changed. `scripts/owner_details.py` adds native tomato, mushroom, pepper, onion and olive toppings to a fitted baked pizza slice, and font-independent DONKEY lettering on the trophy plate. The original PNG pizza remains the earlier reference. Other component drawings remain in `clean_vectors.py` and `familiar_vectors.py`.

The tiger has a separate compact master in `scripts/tiger_vectors.py`: reference-measured ear, brow, stripe, cheek and muzzle curves, with 14 shared material gradients and subtle native bevels. This replaces its 221,207-byte sampled surface with a **9,398-byte SVG** (**2,547 bytes gzip**). It contains 16 paths and 53 gradient stops rather than 211 paths and 4,323 stops. `review/vectors/tiger-review.html` offers a focused PNG/SVG comparison, adjustable size, light/dark backgrounds and an overlay slider. Tiger authoring is selected automatically by the reconstruction script; its size is capped at 16 KiB plain and 4 KiB compressed.

The lion now uses `scripts/lion_vectors.py`: fourteen overlapping mane locks with individually fitted shading, recessed ears, glossy eyes and the PNG's softly triangular cream muzzle. Its **15,948-byte SVG** (**3,839 bytes gzip**) replaces the 195,919-byte sampled surface, a 91.9% reduction. It contains 31 paths, 27 gradients and 118 stops, compared with 229 paths and 3,677 stops previously. `review/vectors/lion-review.html` provides the live PNG/SVG comparison and overlay; `review/vectors/lion/` retains the previous drawing and native render diagnostics. Installed Chrome checks cover 32, 64, 192, 512 and 1024 px, mirrored ear colours, transparent padding and both backgrounds. The reconstruction dispatcher retains the compact author, with the same 16 KiB plain and 4 KiB compressed budgets as tiger. It is a visual reconstruction, with owner review distinct from automated checks.

Monkey uses `scripts/monkey_vectors.py`: editable ear cups, hair tuft, heart-shaped face, glossy eyes, nostrils and smiling mouth, shaded with eleven material gradients. Its **6,005-byte SVG** (**1,770 bytes gzip**) replaces the 104,041-byte sampled master, a 94.2% reduction. It contains nine paths and forty gradient stops. [The focused comparison](review/vectors/monkey-compact/comparison.html) preserves the PNG, previous SVG, unoptimised candidate, overlays and reaction sizes on light/dark backgrounds. Chrome checks cover 32/64/192/512/1024 px. Original PNGs and unrelated SVGs remain byte-for-byte unchanged; shading is a compact reconstruction of the reference's finer soft transitions.

The sacred stone uses `scripts/stone_vectors.py`: the real photograph's uneven outline and twelve individually measured painted glyphs, with four material gradients and native procedural granite. The owner selected compact, realistic texture over encoding the photograph's individual grains. This replaces the 413,657-byte colour-region master with a **10,110-byte SVG** (**4,078 bytes gzip**), a 97.6% reduction, containing ten paths and thirteen gradient stops. Its four rows retain `600 / 000 / 000 / 000`; native raster checks confirm twelve separate glyphs and twelve open counters, and Chrome checks their painted contrast, the eight-pixel margin and 32/64/192/512/1024 px rendering. The author verifies the pinned source hash. `review/vectors/sacred-stone-review.html` is a portable comparison that labels the earlier PNG explicitly and links the real photograph. For local photographic review, run `FORGEMOJI_LOCAL_STONE_REFERENCE=1 node scripts/build-stone-review.mjs`; it uses the pinned photo cache outside the repository and retains its full detail when enlarged. Run `npm run build:svg` before publishing to restore the portable page. Normal distribution builds need no photograph, Python or network request. Individual procedural grains can differ between renderers; the contour and numeral geometry remain native paths. The compact stone is bounded at 32 KiB plain and 8 KiB compressed.

The extra detail raises the plain 163-SVG collection from the previous **1.84 MB** to **9.50 MB**. Individual gzip-compressed vectors total about **1.52 MB**; the reviewed **1.54 MB ZIP** contains all 163 ordinary SVG files and is available from the gallery. Common familiar SVGs are bounded at 256 KiB plain and 48 KiB compressed, with separate budgets for the compact stone and photographic spider. The full familiar collection is capped at 10 MiB plain and 1.8 MiB compressed. The nine brand SVGs and all original PNGs are preserved. `review/vectors/quality-pass.json` records exact sizes, archive integrity, optimiser error and separate before/after reference comparisons. The light/dark comparison sheets show the original PNG, previous SVG and updated SVG. The pizza, trophy engraving and larger star eyes are intentional design changes; the stone is evaluated against the real photograph. Measured similarity does not replace visual acceptance.


Install FFmpeg/FFprobe, librsvg (`rsvg-convert`) and Node 22 or later, then run `npm run build`. It crops each sheet according to the recorded grid, isolates each icon from disconnected neighbouring fragments, scales with Lanczos into 192×192 transparent PNGs with consistent padding, copies the checked-in `sources/vectors/` masters into `svg/`, writes both artwork lists with exact byte counts and SHA-256 hashes, and rebuilds both standalone galleries. `npm test` checks Unicode mapping, tone completeness, PNG dimensions and hashes, SVG/master integrity and manifest consistency. `npm run build:svg` updates just the vector distribution and galleries, preserving the PNGs. `npm run verify:vectors` rasterises every SVG at 32, 192 and 512 px with librsvg, checks transparency and the open doughnut/key contours, and checks the Chrome gallery, tone controls, format switching and mobile layout. It writes light/dark chat-size screenshots and enlarged comparisons to `review/vectors/`. It requires `npm install` and installed Google Chrome; set `FORGEMOJI_CHROME` for another executable path. FFmpeg versions can affect encoded bytes, so compare the checked-in manifest when reproducing an existing release.

Existing owned logos are rasterised for the PNG distribution from the recorded SVG/PNG masters with librsvg and FFmpeg. The eight existing SVG brand masters are preserved in the vector distribution. No API key is needed to rebuild the existing sheets. Regenerating artwork is a separate paid image-generation operation and is not part of the build.

To reauthor the SVG reconstructions, install the Python packages Pillow, NumPy, SciPy and opencv-python, then run `npm run rebuild:vectors`. This optional step rebuilds component drawings and fitted colour surfaces, consults the pinned community stone reference when absent from the local temporary cache, and compacts familiar masters with pinned SVGO 4.1.0. The optimiser retains three-decimal geometry and simplifies fitted gradient stops within a 0.8/255 channel bound; already smaller masters are retained. `npm run optimize:vectors` runs just the compaction and distribution build. The approved happy-face master and existing vector brand masters are retained. `sources/vector-provenance.json` records the source hashes and strategy for each entry. Normal builds use the checked-in SVG masters and need no Python or image-generation API.

To regenerate the size/fidelity evidence and reviewed ZIP, save the previous `svg/` directory and `manifest.json`, save the newly authored `sources/vectors/` masters before optimisation, then run `python3 scripts/report-vector-quality.py --baseline <saved-repository> --unoptimised <saved-masters>`. Rebuild the gallery afterwards to refresh its archive link.
